# 小组共享主题与成员动物首页设计

## 目标

让空间首页的欢迎卡片由小组共同定制：所有成员看到同一个背景主题，右侧动物形象根据小组成员选择的头像自动组合。现有的固定猫兔插画将替换为可复用的头像卡通组件，保证“成员头像”和“首页角色”保持一致。

## 用户体验

空间创建者在“空间设置”中选择首页主题。主题是空间级设置，保存后所有成员在下一次数据刷新或进入首页时看到相同主题。当前主题选择器展示名称、色板和小型预览，保存成功后显示明确的成功状态；保存失败保留原主题并提示错误。

首期提供四套主题：

- **成长紫**：当前欢迎卡片的紫色渐变，作为默认主题。
- **晨光米黄**：温暖、轻快的奶油色背景。
- **薄荷蓝**：清爽、安静的蓝绿色背景。
- **晚霞珊瑚**：活泼的珊瑚和橙色渐变。

首页欢迎卡片右侧显示当前空间的活跃成员头像。按成员加入时间取前两位：一位成员显示一个放大的动物头像，两位成员并排显示；超过两位时，在组合旁边显示“+N 位伙伴”。已退出成员不参与组合，但历史数据仍可正常显示在其他位置。头像没有保存值时继续使用现有的稳定回退映射，因此不会出现空白角色。

## 数据与权限

在 `spaces` 表新增 `theme_id` 字段，使用受限字符串值并设置默认主题 `growth-purple`。增量迁移必须兼容已有空间，已有记录自动获得默认主题，不改写成员或任务数据。

空间汇总接口返回 `space.theme_id`，空间设置接口接受主题 ID。只有现有的空间创建者/空间管理权限可以修改主题；普通成员只能读取。服务端使用白名单校验主题 ID，拒绝未知值，避免把任意 CSS 值写入数据库。

前端共享类型、Supabase 类型和本地数据库迁移保持同步。主题切换成功后通过当前的空间刷新和实时更新机制让所有打开页面最终一致；当前编辑者先更新本地预览，保存失败时回滚。

## 组件设计

新增 `GroupHeroArtwork` 组件，职责只有两件事：接收活跃成员和主题上下文，渲染一到两个 `Avatar`，以及超出人数提示。它不负责读取数据库，也不修改成员数据。

欢迎卡片继续由首页负责文案和操作按钮；主题只通过主题 ID 映射到预定义 CSS 类，背景装饰、文字对比度和按钮颜色由主题样式控制。头像组合使用独立容器，桌面端限制最大宽度和高度，移动端缩小并保持可见，不改变欢迎卡片整体高度。

空间设置新增主题选择区域，使用与现有空间头像选择器一致的键盘操作、焦点样式和保存状态。主题选项显示色板和名称，不要求用户理解 CSS 或内部 ID。

## 边界情况

- 只有已加入且未退出的成员参与首页动物组合。
- 成员头像更新后，空间刷新会重新计算组合。
- 只有一位成员时不显示空的第二个角色位。
- 没有成员数据时使用默认插画占位，避免首页布局跳动。
- 旧空间没有主题字段时按成长紫渲染。
- 主题保存与头像保存互不覆盖，避免并发编辑丢失另一个字段。

- 单元测试覆盖四套主题白名单、主题默认值、成员头像组合的一位/两位/多人/退出成员场景。
- 组件测试覆盖主题选择、权限显示、保存失败回滚和首页头像组合。
- 集成测试覆盖空间主题读取、创建者更新、普通成员拒绝更新以及旧空间迁移默认值。
- 运行 TypeScript、ESLint、相关 Vitest 测试和生产构建。
- 在桌面和手机断点检查欢迎卡片高度、文字对比度、头像不溢出和主题切换后的实时刷新。
