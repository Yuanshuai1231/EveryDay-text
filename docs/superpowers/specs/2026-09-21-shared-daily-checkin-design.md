# 多人每日打卡网站设计说明

日期：2026-09-21

## 1. 产品目标

为朋友或小团队提供一个私密的共同打卡空间。成员可以记录每天上午和下午做了什么，创建并完成每日任务，查看其他成员的任务和工作记录，并通过群聊与私聊互动。产品采用卡通风格，优先保证每天打开、快速记录和多人同步的体验。

首版采用“空间导航优先”的信息架构：今日打卡、任务清单、群聊、成员管理分别有清晰入口；空间首页展示今日状态、成员动态和完成情况。

## 2. 已确认的产品决策

- 使用范围：朋友或小团队的私密空间。
- 加入方式：创建者输入昵称和空间名称生成邀请码；成员输入昵称和邀请码加入。
- 身份方式：加入后生成浏览器成员会话令牌并保存于 HttpOnly Cookie；同一设备可保持身份，换设备需要重新加入。
- 记录可见性：空间成员互相可见上午/下午记录和任务。
- 记录保存：输入后自动保存草稿；用户点击“完成打卡”后标记当天完成，完成后仍可修改内容。
- 任务所有权：每项任务只有一个创建者；创建者可以编辑、勾选和删除，其他成员只读。
- 聊天范围：空间群聊加成员私聊；首版支持文字和表情，不包含图片上传、语音和任务评论。
- 时间规则：空间默认使用北京时间；成员可以补写或修改历史日期。
- 首页方向：空间导航优先。
- 技术路线：Next.js + TypeScript + Supabase PostgreSQL + Supabase Realtime。

## 3. 页面和核心流程

### 3.1 加入流程

1. 创建者输入昵称和空间名称。
2. 系统创建空间并生成邀请码，进入空间首页。
3. 新成员输入昵称和邀请码。
4. 服务端校验邀请码后创建成员和浏览器会话，进入空间首页。
5. 邀请码错误或空间不存在时展示明确错误，不创建成员。

### 3.2 空间首页

首页显示空间名称、当前日期、今日成员完成情况、任务完成统计和最近动态。左侧为桌面导航，包含今日打卡、任务清单、群聊、成员；移动端改为底部导航，平板端使用可收起的左侧导航。

### 3.3 今日打卡

用户可通过日期选择器查看当天或历史日期。页面包含上午记录卡片、下午记录卡片和当天完成打卡按钮。文本输入自动保存，显示“保存中 / 已保存 / 保存失败”状态；点击完成后显示完成时间和完成状态。完成状态不等同于任务全部完成。

### 3.4 任务清单

任务按目标日期展示，包含创建者头像、任务标题、备注、完成状态和更新时间。本人任务显示编辑、删除和勾选控制；其他成员任务显示只读状态。默认保留未完成任务在原日期，不在午夜自动消失或复制。

### 3.5 聊天

空间默认创建一个群聊。成员可从成员列表进入一对一私聊。消息显示发送者、时间和发送状态，服务端时间作为排序依据。发送失败时显示失败标记和重试按钮；用户阅读旧消息时，新消息只显示“有新消息”提示，不强制滚动到底部。

### 3.6 成员管理

空间创建者可以查看邀请码、移除成员；普通成员可以退出空间。被移除或退出的成员保留历史记录，但立即失去空间读取、写入和实时订阅权限。首版不提供公开空间发现和用户搜索。

## 4. 数据模型和权限

核心表：

- `spaces`：空间名称、创建者、邀请码摘要、空间时区。
- `members`：空间成员、昵称、头像颜色、创建者标记、加入时间。
- `member_sessions`：成员会话令牌哈希、成员 ID、最后活跃时间。
- `daily_logs`：空间、成员、工作日期、时段（morning/afternoon）、内容、更新时间。
- `daily_checkins`：空间、成员、工作日期、完成时间。
- `tasks`：空间、创建者、目标日期、标题、备注、完成状态、更新时间。
- `conversations`：空间、会话类型（group/direct）。每个空间默认一个群聊。
- `conversation_members`：会话与成员的关联。
- `messages`：会话、发送者、正文、服务端时间、客户端幂等 ID。

约束：

- `daily_logs` 对“空间 + 成员 + 日期 + 时段”建立唯一约束。
- `daily_checkins` 对“空间 + 成员 + 日期”建立唯一约束。
- 私聊双方在同一空间只能有一个会话。
- 消息使用客户端幂等 ID，网络重试不会产生重复消息。
- 每个写接口都在服务端重新验证空间成员身份和资源所有权；前端隐藏按钮不作为权限控制。
- Supabase RLS 限制空间、成员、记录、任务、会话和消息的读取及写入范围。

## 5. 功能接口边界

- 空间：创建空间、使用邀请码加入、读取成员、移除成员、退出空间。
- 打卡：按日期读取、保存上午记录、保存下午记录、完成当天打卡。
- 任务：读取日期任务、创建任务、修改本人任务、勾选本人任务、删除本人任务。
- 聊天：读取会话、创建私聊、分页读取历史消息、发送消息、重试失败消息。
- 实时事件：`daily_log.updated`、`checkin.completed`、`task.updated`、`message.created`、`member.changed`。

## 6. 响应式和视觉设计

视觉基调使用暖米白背景、深紫导航、黄色主按钮、柔和珊瑚和浅蓝辅助色、圆角卡片和小动物头像。卡通元素用于头像、状态和空状态插画，正文保持高对比度和清晰层级。

- 手机端（小于 768px）：底部导航；上午和下午记录上下排列；任务单列；群聊和私聊使用全屏会话页；创建任务按钮固定在右下角；输入框适配软键盘和刘海屏安全区域。
- 平板端（768–1023px）：可收起左侧导航；上午和下午记录双栏；任务列表与成员动态可并排；聊天使用主内容区加成员列表双栏。
- 桌面端（不小于 1024px）：完整左侧空间导航；主内容使用卡片网格；设置最大内容宽度，避免超宽屏文本拉伸。
- 所有可点击控件触摸目标不小于约 44×44px，同时支持鼠标和触摸。
- 移动端竖屏、平板横屏和桌面宽屏均需要覆盖核心流程测试。

## 7. 实时、离线和错误处理

- 任务勾选、打卡状态、记录更新时间、成员变化和聊天消息通过 Realtime 同步。
- 记录输入先进入本地草稿状态，再提交服务端；显示保存中、已保存或失败。
- 断网时保留未提交文本，重连后按最后一次本地编辑时间重试；冲突时提示用户选择保留版本，不静默覆盖。
- 聊天消息先展示发送中状态，服务端确认后变为已发送；失败消息保留正文并支持重试。
- 被移除成员的实时订阅关闭，后续 API 写入统一返回无权限错误。

## 8. 验收标准

1. 创建者可以创建空间并获得邀请码，成员可以用昵称和邀请码加入。
2. 未加入成员无法通过页面或接口读取空间数据。
3. 上午、下午记录自动保存，刷新、断网重连和历史日期补写不会丢失或串日。
4. 完成打卡状态可被其他成员实时看到，且与任务完成数量独立统计。
5. 他人任务只读，本人任务可编辑和勾选；直接调用接口也不能越权修改。
6. 群聊、私聊支持历史分页、快速连发、失败重试和去重。
7. 移除或退出后立即失去读取、写入和实时订阅权限，历史数据仍保留。
8. 手机、平板、桌面三种布局均能完成加入、打卡、任务和聊天主流程。

## 9. 首版明确不做的内容

- 手机号、邮箱、第三方账号登录。
- 公开社区、空间搜索和公开分享链接。
- 图片、文件、语音、视频消息。
- 多级组织架构、部门统计、审批和排行榜。
- 自动重复任务、任务评论和复杂提醒系统。
